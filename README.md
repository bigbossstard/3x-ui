# 3x-ui Client-Host

Патч для [3x-ui](https://github.com/MHSanaei/3x-ui), добавляющий назначение **Host для отдельных клиентов**.

Основная задача — управлять тем, какие Host-группы используются при генерации подписки конкретного клиента, не изменяя существующую связь клиент → inbound.

## Что добавляет патч

- Назначение одного или нескольких Host Group конкретному клиенту.
- Сохранение существующей логики `client_inbounds` и конфигурации Xray.
- Клиенты без назначений продолжают работать в legacy-режиме и получают все применимые включённые Host.
- После очистки всех назначений клиент автоматически возвращается в legacy-режим.
- Если назначенная Host Group не имеет подходящего Host на конкретном inbound, legacy-fallback не используется.

Подробная техническая схема: [`docs/client-host-assignment.md`](docs/client-host-assignment.md).

## Требования

- Уже установленный и рабочий **3x-ui**.
- Linux **amd64 / x86_64**.
- `systemd` и сервис `x-ui`.
- Доступ сервера к GitHub.

Установщик Client-Host не является заменой обычного установщика 3x-ui: сначала устанавливается оригинальный 3x-ui, затем поверх него подключается Client-Host.

## Установка

### 1. Установить оригинальный 3x-ui

Используйте официальный установщик upstream:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/MHSanaei/3x-ui/main/install.sh)
```

Проверьте, что панель запущена:

```bash
systemctl is-active x-ui
```

Должно вернуться:

```text
active
```

### 2. Установить Client-Host

```bash
curl -fsSL https://raw.githubusercontent.com/bigbossstard/3x-ui/client-host/tools/install-client-host.sh | sudo bash
```

Установщик:

- проверяет существующую установку 3x-ui;
- сохраняет проверенную копию оригинального `/usr/local/x-ui/x-ui` **до применения патча**;
- устанавливает `xch` и managed updater;
- отключает старый автоматический timer Client-Host, если он остался от предыдущих версий;
- не включает периодические автоматические обновления.

После установки откройте менеджер:

```bash
xch
```

Для первого применения текущего патча выберите **1) Обновить** или выполните:

```bash
xch update
```

## Управление

| Команда | Назначение |
| --- | --- |
| `xch` | Интерактивное меню |
| `xch update` | Установить последний опубликованный Client-Host release |
| `xch rollback` | Откатить последний сохранённый бинарник |
| `xch status` | Показать версию, состояние сервиса и доступность обновления |
| `xch remove` | Вернуть оригинальный 3x-ui и полностью удалить Client-Host |

Интерактивное меню:

```text
1) Обновить
2) Откатить
3) Статус
4) Удалить
0) Выход
```

## Как работает обновление

Каждая сборка Client-Host публикуется как отдельный immutable release с полным commit SHA.

`client-host-current` — это только указатель на последний опубликованный release. Сам бинарник скачивается по неизменяемому URL конкретного commit.

Перед заменой бинарника updater:

1. получает текущий release;
2. скачивает бинарник и SHA-256 файл;
3. проверяет SHA-256;
4. проверяет версию бинарника;
5. сохраняет текущий `x-ui` в backup;
6. заменяет только бинарник;
7. запускает `x-ui` и проверяет, что сервис стал active.

Если новый бинарник не запускается, предыдущий бинарник восстанавливается автоматически.

**База данных, настройки панели, Xray-конфигурация и остальные файлы установки при обновлении бинарника не заменяются.**

## Откат

```bash
xch rollback
```

Откат восстанавливает последний сохранённый бинарник Client-Host и проверяет запуск `x-ui`.

Rollback — это не удаление Client-Host.

## Полное удаление Client-Host

```bash
xch remove
```

Удаление должно вернуть узел в состояние обычного 3x-ui:

- восстанавливается сохранённый оригинальный бинарник 3x-ui;
- проверяется запуск `x-ui`;
- удаляются `xch` и managed updater;
- удаляются Client-Host backups;
- удаляются старые Client-Host systemd units;
- **БД и конфигурация 3x-ui не изменяются.**

Если восстановленный оригинальный бинарник не запускается, updater автоматически возвращает предыдущий Client-Host бинарник и не завершает удаление.

## Безопасность публикации

Публикация разделена на две части:

- **immutable release** — конкретный проверенный набор бинарников и инструментов;
- **`client-host-current`** — указатель на последний опубликованный release.

Устаревший workflow не должен публиковать собственную сборку или передвигать `client-host-current`. Сборка выполняется только после прохождения предусмотренной CI-проверки для соответствующего commit.

## Важно

- Client-Host сейчас публикуется только для **amd64 / x86_64**.
- Автоматические периодические обновления отключены.
- `xch update` обновляет только Client-Host бинарник и управляемые инструменты.
- `xch rollback` откатывает бинарник, но не меняет БД.
- `xch remove` предназначен именно для полного удаления патча и возврата к оригинальному 3x-ui.
- Ветка [`client-host`](https://github.com/bigbossstard/3x-ui/tree/client-host) содержит патч; оригинальный upstream-проект находится в [`MHSanaei/3x-ui`](https://github.com/MHSanaei/3x-ui).
